## errata

```text
errata checks the claims a repository makes about itself. Each check in the
config is a program errata runs, or a rule over values errata reads from the
repository's files. errata prints every claim shown false (an erratum) with
the reason the check was written, and says how many checks ran, how many it
skipped, and why it skipped each.

errata never applies anything. It reads files and runs the programs the
config names. The only files it writes itself are the ones a --output flag
of errata check names, each through a temporary file beside it, and the
plugins errata plugin install installs, with errata.lock.

The config
  errata check and errata list read errata.yaml in the repository root.
  --root names the root and defaults to the working directory. --config
  names another file in place of <root>/errata.yaml; errata looks for no
  other file and reads no environment variable to find one.

Flags
  --version (default off)
      Print the version of this errata binary and exit 0, the same line
      errata version prints.

Exit codes
  0  the command did what it was asked. For errata check, every check that
     ran found its claim true.
  1  errata check found at least one erratum or unknown, or, with
     --fail-on-skip, skipped at least one check.
  2  bad flags or an unknown command, a config that does not load, or an
     --output file errata cannot write.

errata with no command prints this help and exits 0. errata help <command>
prints the help of one command, as errata <command> --help does, and exits
0 even for a command errata does not know.

Usage:
  errata [command]

Examples:
  # Check the repository in the working directory.
  errata check

  # See which checks a config holds, with the defaults filled in.
  errata list --config ci/errata.yaml

  # Print the version, as errata version does.
  errata --version

  # Check the working directory with the image in place of a binary.
  docker run --rm -v "$PWD:/repo" -w /repo fklement/errata check

Available Commands:
  check       Run the checks in errata.yaml and print the errata
  completion  Print a shell's completion script for errata
  help        Print the help of a command
  list        Print the checks errata.yaml holds, as errata check loads them
  plugin      Install the plugins errata.lock pins
  version     Print the errata version

Flags:
  -h, --help      help for errata
      --version   print the errata version, as errata version does

Use "errata [command] --help" for more information about a command.
```

## errata check

```text
Run every check in the config that errata can reach, skip the rest with the
reason, and print the errata and the coverage: how many checks ran, how many
it skipped, and the gap behind each skip.

A repo check runs on the files. A live or applied check needs a provider for
a running system, which errata does not have yet, so errata skips it and
prints a line naming the check, its scope and the gap, such as "skipped
pinned-image (live): no provider can read a live system". A program check
runs with the repository root as its working directory. When two or more
program or generated checks that last took a second or more can run at
once, each runs in a copy of the repository of its own, made in the user's
cache with the working tree's changes and ignored files on it, so nothing
one writes reaches the repository or another check; in_place: true keeps a
check in the repository. A repository whose ignored files hold more than
32 MiB runs every check in place.

errata check never applies anything. Outside the user's cache it writes no
file but the ones --output names; in the cache it keeps the copies while
they run and how long each check took. It prints the report whatever the
run found.

Flags
  --root DIR (default .)
      The repository root. Checks run with it, or a copy of it, as their
      working directory, and errata reads <root>/errata.yaml unless
      --config names a file.
  --config FILE, -c FILE (default <root>/errata.yaml)
      The config file. A relative FILE is read from the working directory,
      not from --root, as a shell redirect is. --root still sets where the
      checks run, so --root repo --config ci/errata.yaml reads the config
      from ci/ and runs the checks in repo.
  --format NAME, -f NAME (default text)
      What goes to stdout: junit, sarif or text.
  --output FORMAT=PATH, -o FORMAT=PATH (default none, repeatable)
      Also write the report in FORMAT, any name --format takes, to the file
      PATH. --format still picks stdout, so --output junit=errata.xml
      --output sarif=errata.sarif writes both files and prints the text.
  --fail-on-skip (default off)
      A skipped check fails the run with exit code 1, as an unknown does.
  --all-values (default off)
      A false assert prints every value its rule read. Without it, an assert
      that is an all over an extractor prints only the values the all found
      false, and counts the rest.

Exit codes
  0  every check that ran found its claim true.
  1  at least one erratum (a claim shown false) or unknown (a check that
     could not evaluate), or, with --fail-on-skip, at least one skip.
  2  bad flags, a config that does not load, or an --output file errata
     cannot write. errata runs no check when it exits 2 before the run.

--fail-on-skip
  A CI gate that must not pass on checks that never ran, such as live
  checks in a job with no cluster, runs errata check --fail-on-skip. A skip
  then fails the run as an unknown does: exit code 1, and no erratum, since
  the check showed no claim false. It stays a skip, with its gap under the
  coverage line, and every format marks it as a failure. The text coverage
  line ends "A skip fails this run.", JUnit writes the skip as an <error>
  whose message is "skipped: " and the gap, and SARIF writes its
  notification at level error and sets executionSuccessful to false.

--all-values
  An assert such as addresses.all(a, a.endsWith('@example.com')), or
  by_file(fences).all(f, ...), is false because of some of its members. The
  message of such an assert, when false, shows the values of those members,
  each with its file and line: a value of addresses, or every value of the
  rule in a file of by_file(fences). A line then counts the values it left
  out. --all-values adds every value of the rule after them, which is what
  any other false assert shows. The verdicts are the same either way.

--output
  The exit code and each format's content are the same as without it, and
  errata writes every file whatever the run found. PATH is relative to the
  working directory, as a redirect's is. errata writes each file to a
  temporary file in its directory and renames it into place, so PATH holds
  the old file or the whole report, never part of one. A run that is
  killed leaves its temporary file, .<name>.<random>.tmp, beside PATH. A new
  file's mode is 0666 less the umask, and a file that is there keeps its
  mode.

  These exit 2 before any check runs: a value without =, a format errata
  does not know, a PATH another --output names, a PATH that is the config,
  and a file errata cannot create. An output is the config when it is the
  file the config was read from, through the config's symbolic links or a
  hard link. An output that is itself a symbolic link to the config is
  replaced, and the config is left alone. A file errata cannot write after
  the run exits 2 too, in place of 1, and errata still prints the report
  and writes every other file.

Control characters
  The text report writes every control character a file or a program's
  output holds, such as ESC or CR, as its escape (\x1b, \r), and every byte
  that is not UTF-8 as \xNN; it drops a CR before a newline. The direction
  controls (U+061C, U+200E, U+200F, U+202A to U+202E and U+2066 to U+2069)
  and the separators U+2028 and U+2029 are escapes too (\u202e). An error
  on stderr, which can quote the config, takes the same escapes. No file in
  the repository can clear the terminal, overwrite a line, reorder one or
  set a link in it. JUnit and SARIF write DEL, the C1 controls and the
  direction controls as character references (&#x9B;) in JUnit and as JSON
  escapes (\u009b) in SARIF, and a reader gets the text back as it was.

Usage:
  errata check [flags]

Examples:
  # Check the repository in the working directory.
  errata check

  # Check another checkout, with a config kept outside it.
  errata check --root ../infra --config infra-errata.yaml

  # In CI: print the text report, keep JUnit for the test report, and
  # fail on a check that was skipped.
  errata check --output junit=errata.xml --fail-on-skip

  # SARIF on stdout, for GitHub code scanning.
  errata check -f sarif > errata.sarif

  # Print every value a false assert read, not only those its all found
  # false.
  errata check --all-values

Flags:
      --all-values           a false assert prints every value its rule
                             read, not only those its all found false
  -c, --config FILE          the config FILE (default <root>/errata.yaml)
      --fail-on-skip         exit 1 when a check was skipped, as on an unknown
  -f, --format NAME          the NAME of the format on stdout: junit,
                             sarif, text (default "text")
  -h, --help                 help for check
  -o, --output FORMAT=PATH   also write the report in FORMAT to the file
                             PATH, as FORMAT=PATH; repeatable
      --root DIR             the repository root DIR (default ".")
```

## errata completion

```text
Print a script that has a shell complete errata's commands and flags.
errata completion <shell> prints the script for one shell: bash, zsh, fish
or powershell. The script asks errata itself for the completions as you
type, so it follows the binary on the PATH. errata completion with no shell,
or with a name that is no shell, prints this help.

Exit codes
  0  errata printed the help, for a name that is no shell too.
  2  a flag other than --help.

Usage:
  errata completion [command]

Examples:
  # Complete errata in this bash session.
  source <(errata completion bash)

  # Complete errata in every new fish session.
  errata completion fish > ~/.config/fish/completions/errata.fish

Available Commands:
  bash        Print the completion script for bash
  fish        Print the completion script for fish
  powershell  Print the completion script for PowerShell
  zsh         Print the completion script for zsh

Flags:
  -h, --help   help for completion

Use "errata completion [command] --help" for more information about a command.
```

## errata list

```text
Print every check the config holds, as errata check loads it, with the
values errata check would run it with and the defaults filled in. A program
that needs to know what errata will run reads errata list --format json
instead of parsing errata.yaml itself.

errata list runs nothing and reads none of the files the checks name. It
reads the config with the loader errata check uses, so a config that check
refuses, list refuses with the same message.

Flags
  --root DIR (default .)
      The repository root. errata reads <root>/errata.yaml unless --config
      names a file.
  --config FILE, -c FILE (default <root>/errata.yaml)
      The config file. A relative FILE is read from the working directory,
      not from --root.
  --format NAME, -f NAME (default text)
      What goes to stdout: json or text.

Exit codes
  0  the config loaded, and errata printed its checks.
  2  bad flags, or a config that does not load.

Control characters
  The text format writes control characters, bytes that are not UTF-8 and
  the direction controls as escapes, as the text report of errata check
  does. The JSON writes DEL, the C1 controls and the direction controls as
  JSON escapes (\u009b), and a reader gets the text back as it was.

Usage:
  errata list [flags]

Examples:
  # The checks in <root>/errata.yaml, as text.
  errata list

  # The checks of another config, as JSON for a program.
  errata list --root ../infra -c infra-errata.yaml --format json

Flags:
  -c, --config FILE   the config FILE (default <root>/errata.yaml)
  -f, --format NAME   the NAME of the format on stdout: json, text
                      (default "text")
  -h, --help          help for list
      --root DIR      the repository root DIR (default ".")
```

## errata plugin

```text
Install the plugins a repository's checks read. A plugin is a program that
reads one more kind of file for errata, such as CSV. errata installs one
from errata's own GitHub releases, checks it against the checksums its
release published, and pins it in errata.lock; every run checks the plugin
against the lock before it starts it, and a run never downloads anything.

errata plugin with no command prints this help.

Exit codes
  0  errata printed the help.
  2  a command or a flag errata does not know.

Usage:
  errata plugin [command]

Examples:
  # Install the CSV plugin and pin it in errata.lock.
  errata plugin install csv

  # In CI, install every plugin errata.lock pins.
  errata plugin install

Available Commands:
  install     Install plugins into the cache and pin them in errata.lock

Flags:
  -h, --help   help for plugin

Use "errata plugin [command] --help" for more information about a command.
```

## errata plugin install

```text
Install plugins into the user's cache and pin them in errata.lock.

errata plugin install csv downloads errata-ext-csv for this system from
errata's releases, tagged errata-ext-csv/v<version>, and checks it against
errata-ext-csv_checksums.txt of the same release. It sends the build the
plugin protocol's describe request, as a run does, keeps it in the cache
under its sha256, and writes the version and the sha256 of every platform's
build into errata.lock. Commit the lock. csv@0.1.0 names a version; without
one errata installs the version the lock pins, else the newest release that
is neither a draft nor a prerelease.

With no name, errata installs every plugin the lock pins, at the pinned
version: what a CI job runs before errata check. A plugin the lock pins from
a file cannot be fetched again, and errata stops on it unless the cache or
the vendored directory holds it.

Once a version is in the lock, errata refuses a release or a mirror that
serves other bytes, and never rewrites the pin: delete the plugin's lines
from errata.lock to pin it anew. errata writes errata.lock last, and only
when every plugin installed, in its own form: it keeps the comment lines at
the top of the file and drops every other comment. A failed install leaves
the lock as it was, at most files in the cache no lock pins, and in
.errata/plugins whole files git status shows. Every download is at most
256 MiB, and one fails when its server sends no answer within 30 s, or
nothing for 60 s while errata reads the body.

A run looks for plugins in .errata/plugins alone once the repository has
it, so while it is there every install vendors what it installs, as
--vendor does, and says so.

errata names no plugin it does not install from errata's releases. A plugin
from elsewhere comes from a file, or from an https URL with the sha256 you
give, which errata checks before it keeps the file; errata vouches only
that the bytes match. The first install of a URL is for this platform, and
names the plugin's version; --platform then adds another platform's build,
which errata checks and does not run.

Flags
  --root DIR (default .)
      The repository root, which holds errata.lock and .errata/plugins.
  --source URL (default $ERRATA_PLUGIN_SOURCE, else errata's releases)
      A mirror of errata's releases: https://<host>/<path>, or a directory
      as file:///<path>, holding each release's assets under its tag, such
      as errata-ext-csv/v0.1.0/. A mirror has no API, so name a version or
      pin one.
  --trust-source (default off)
      Pin a version the lock does not pin yet through --source or
      $ERRATA_PLUGIN_SOURCE. Without it errata refuses, since the mirror
      would serve the checksums file too and so choose the pin. Pin each
      version once from errata's releases instead, where you can.
  --vendor (default off, on when .errata/plugins exists)
      Also write every platform's build the lock pins, the release's notices
      file and errata's LICENSE into .errata/plugins, so CI with no network
      runs from the commit. errata never writes over a file there, and
      leaves a LICENSE or notices file that differs, saying so.
  --file PATH (default none)
      Install the build at PATH, named errata-ext-<name>, for this platform,
      and pin it as a file.
  --url URL (default none)
      Install the build at the https URL, checked against --sha256, and pin
      it with its URL.
  --sha256 HEX (default none)
      The sha256 of the build at --url, as 64 hex digits.
  --platform OS/ARCH (default the platform errata runs on)
      The platform the build at --url is for, such as darwin/arm64. Another
      platform than this one names the plugin, which the lock pins from a
      URL already.
  --replace (default off)
      Let --file or --url take the place of a release the lock pins.

Environment
  ERRATA_PLUGIN_SOURCE  the plugin source, when --source is not given.
  GITHUB_TOKEN          sent to api.github.com alone, when errata looks up
                        the newest release; never to a mirror or a URL.

Exit codes
  0  every plugin is installed, and errata.lock pins it.
  2  bad flags, or a plugin errata did not install; the lock is unchanged.

Usage:
  errata plugin install [<name>[@<version>]...] [flags]

Examples:
  # Install the newest CSV plugin, or the version errata.lock pins.
  errata plugin install csv

  # Install every plugin errata.lock pins, and commit them for CI.
  errata plugin install --vendor

  # Install a pinned version from a mirror; pin a new one from it.
  errata plugin install csv --source file:///srv/errata-plugins
  errata plugin install csv@0.2.0 --source https://m.example --trust-source

  # Install a build of your own, in place of the release.
  errata plugin install --file ./bin/errata-ext-csv --replace

  # Install a plugin from a URL with its sum, then another platform's.
  errata plugin install --url https://p.example/errata-ext-nginx \
    --sha256 <its sha256>
  errata plugin install nginx --platform darwin/arm64 \
    --url https://p.example/errata-ext-nginx_darwin_arm64 --sha256 <its sha256>

  # Install what another checkout's errata.lock pins.
  errata plugin install --root ../infra

Flags:
      --file PATH          install the build at PATH, pinned as a file
  -h, --help               help for install
      --platform OS/ARCH   the platform OS/ARCH the build at --url is for
                           (default the platform errata runs on)
      --replace            let --file or --url take the place of a release
                           the lock pins
      --root DIR           the repository root DIR (default ".")
      --sha256 HEX         the sha256 of the build at --url, as 64 HEX digits
      --source URL         a mirror of errata's releases, as an https or
                           file URL (default $ERRATA_PLUGIN_SOURCE, else
                           errata's releases)
      --trust-source       pin a version the lock does not pin yet through
                           the mirror
      --url URL            install the build at the https URL, checked
                           against --sha256
      --vendor             also write every platform's build into
                           .errata/plugins
```

## errata version

```text
Print the version of this errata binary on one line. A release build prints
its tag, such as v0.2.4, and make build prints what git describe gives, such
as v0.2.4-3-g8ade832 three commits after it. Any other build prints the
version Go records in the binary: the module version for go install at a
release, and a pseudo-version, such as v0.2.5-0.20261103212526-8ade832ca96d,
for a build in a git checkout or a go install at a commit, with +dirty when
the checkout has changes. A build without that record prints dev.

errata --version prints the same line. errata version reads no config, and
takes no argument and no flag but --help (-h).

Exit codes
  0  errata printed its version.
  2  an argument, or a flag other than --help.

Usage:
  errata version [flags]

Examples:
  # The version of the binary on the PATH.
  errata version

  # The version of the image.
  docker run --rm fklement/errata version

Flags:
  -h, --help   help for version
```
